## Highlights

harlite 0.5.0 addresses all 13 findings from the September code review, improving privacy processing, file safety, response fidelity and CLI reliability.

- Remove unscanned secret-bearing metadata from privacy outputs and inspect gzip/Brotli bodies before configured redaction or PII matching.
- Protect input files from export collisions and publish completed output files atomically.
- Preserve repeated HTTP headers and serve compressed responses with the correct bytes and headers.
- Retain available body data when merging databases.
- Bound plugin execution and output, validate mock status codes and replay rates, and fix relative output filenames.
- Keep database inspection read-only, including legacy schema compatibility.
- Upgrade the HTTP stack to address [RUSTSEC-2026-0258](https://rustsec.org/advisories/RUSTSEC-2026-0258.html), with h2 0.4.19 in the lockfile.

## Upgrade notes

- Privacy output now discards unscanned HAR extensions, cache metadata and duplicated initiator/redirect URLs. This intentionally changes round-trip fidelity. Body redaction still requires configured patterns; PII detection retains its URL/body scope. Warnings identify binary or unavailable bodies that cannot be inspected.
- Repeated header values are stored as ordered JSON arrays; single values remain strings. Existing databases remain readable. Update custom SQL that assumes every header value is a string.
- Plugins default to a 30-second deadline and an 8 MiB output cap per stream. Adjust `timeout_secs` and `max_output_bytes` in plugin configuration for larger workloads.
- Unix sensitive staging files use mode 0600. Windows retains inherited directory ACLs. Unix plugin cleanup covers the process group; Windows cleanup covers the direct child.
- Legacy database inspection can require a full in-memory snapshot.

## Downloads and verification

Native archives are available for Linux AMD64/ARM64, macOS AMD64/ARM64, and Windows AMD64. Each archive contains the binary, README, changelog and MIT license. Binaries include all Cargo features, including Parquet export.

Each archive and `SHA256SUMS` is covered by a keyless GitHub artifact attestation backed by Sigstore. Download the matching archive and `SHA256SUMS`, then verify:

```bash
grep 'harlite-v0.5.0-linux-amd64.tar.gz' SHA256SUMS | sha256sum --check -
gh attestation verify harlite-v0.5.0-linux-amd64.tar.gz --repo brucehart/harlite
```
